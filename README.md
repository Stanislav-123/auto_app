# Бот завода приложений

Телеграм-бот на python-telegram-bot. Завод стартует только командой `/app`: либо `/app` и следующим сообщением текст о приложении, либо текст сразу после команды. Обычное пересланное сообщение само по себе ничего не запускает. Дальше шаги идут сами — кампания в Binom, карточка в CRM, домен, бэкенд. Архив, тематику, домен (если его не было в тексте) и ключи Facebook бот просит отдельно, их можно присылать обычным ответом.

Пока у одного пользователя идёт завод, следующий `/app` с текстом приложения встаёт в очередь и запускается сам, когда текущий закончится или его отменят. Одновременно крутится только один завод; разные пользователи по-прежнему работают параллельно. `/cancel` отменяет текущее приложение и сразу берёт следующее из очереди. `/clear_queue` чистит очередь и не трогает текущий завод. `/domain` и расшарка AppsFlyer в эту очередь не входят.

Прогресс пишется в `data/workflows` и подхватывается после перезапуска.

## Настройка

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python bot.py
```

`ALLOWED_USER_IDS` — Telegram user id через запятую. Пустой список никого не пускает.

Ключи AppsFlyer и ссылка трекера Binom (`BACKEND_BINOM_URL`, без `?key=`) берутся только из `.env`.

## Шаги

0. `/app` — прислать данные приложения. Повторный `/app` с текстом, пока идёт другой завод, ставит приложение в очередь.
1. Разбор сообщения.
2. Кампания в Binom. Если имя уже есть — берём её, не клонируем.
3. Карточка в CRM. Если bundle/store id или имя уже есть — берём id, не создаём заново.
4. Домен: `app_domain` через `/app/update` и `domain` в правилах. Имя сверяется со справочником доменов.
5. Бэкенд: iOS — панель с cookie, Android — basic auth, перед этим ключи Facebook.

Ошибка останавливает цепочку и даёт кнопку «Повторить шаг». Уже сделанные шаги второй раз не гоняются. Id карточки CRM сохраняется сразу после создания, до выдачи доступа командам.

## FCM ключ (Android)

После ZIP-архива для Android бот сам берёт ключ сервисного аккаунта Firebase и кладёт весь JSON строкой в `fcm_key` карточки CRM. Проект ищется по строке «Название в Firebase» из сообщения: id проекта, ссылка на консоль или отображаемое имя.

Как работает: открывает Firebase console в постоянном профиле Chrome (`GOOGLE_PROFILE_DIR`, по умолчанию `data/google_profile`). Если проекта не видно — ищет приглашение (на странице консоли или письмо в Gmail) и принимает его. Потом Project settings → Service accounts → Generate new private key, скачанный файл проверяется (`type: service_account`, `project_id`, `private_key`, `client_email`). Ключ сохраняется в файле workflow, при повторе шага новый не создаётся. В чат и в лог ключ не пишется.

Если что-то не вышло, бот присылает скриншот и причину и просит прислать JSON-файл руками, как с APNS.

Realtime Database: если в сообщении есть строка `Ключи firebase - combo, reflex`, бот делит домен на две непустые части около середины и пишет первую в первый ключ, вторую во второй (порядок как в сообщении). Например `example.com` → `combo = examp`, `reflex = le.com`. Существующие ключи правит, недостающие создаёт, если всё уже стоит — ничего не трогает. Если не вышло — скриншот и значения, которые надо поставить руками; на ключ FCM и CRM это не влияет. Домен берётся из сообщения; если его ещё нет на шаге CRM, бот так и напишет.

Если телефон для 2FA недоступен, можно подложить экспорт кук Google (Cookie-Editor JSON или Netscape). Путь в `GOOGLE_COOKIES_FILE`, бот грузит их в профиль сам. Проверить:

```bash
python scripts/load_cookies.py            # путь из GOOGLE_COOKIES_FILE
python scripts/load_cookies.py data/coockie.txt
```

Вход в Google один раз руками, окно видимое:

```bash
python scripts/google_login.py
```

Скрипт сам вводит `GOOGLE_EMAIL` и `GOOGLE_PASSWORD` из `.env`. Если Google просит подтверждение на телефоне, ждёт до 2 минут. Если пишет «браузер небезопасен» или показывает капчу — останавливается, скриншот в `logs/google-login.png`. `--manual` — войти руками и нажать Enter. Бот при разлогине тоже входит сам тем же способом. Браузер: `BROWSER_PATH` из `.env`, иначе Яндекс Браузер (`%LOCALAPPDATA%` или `Program Files\\Yandex\\YandexBrowser\\Application\\browser.exe`), потом Chrome, потом Chromium. Профиль всегда отдельный (`GOOGLE_PROFILE_DIR`), не основной профиль браузера. `FB_HEADLESS=0` по умолчанию (Google часто не пускает headless), `FB_TIMEOUT_MS` — таймаут шага.

## /domain

Покупка на Dynadot (`DYNADOT_API_KEY`), зона в Cloudflare и запись в CRM. Белый список тот же.

Три режима, бот спрашивает кнопкой:

- Пачка: число N, только `.top` и `.sbs`. Имена вроде `backend42.top` / `dev7back.sbs`. Берём те, что свободны и не дороже `DOMAIN_MAX_PRICE_USD` (по умолчанию 3).
- Конкретные имена: цену показываем. Дороже лимита не выкидываем молча, спрашиваем.
- Только настройка: домены уже куплены. Список можно вставить столбиком, через запятую или из таблицы. Покупки нет.

Перед запуском список и кнопка. Дальше на каждый домен один аккаунт Cloudflare со статусом 0 в CRM: зона, A на `DOMAIN_DEFAULT_IP` (по умолчанию `5.75.214.90`, можно прислать другой), SSL flexible, NS в Dynadot, аккаунт помечается занятым, карточка домена в CRM. Для уже купленных срок берётся из Dynadot (`domain_info`), если его нет — сегодня плюс год. Ошибка по одному домену не останавливает остальные; упавший шаг можно повторить. Ключи и пароли в чат и в лог не пишутся.

## Меню

`/start`, `/menu` и `/help` показывают кнопки:

- Заведение приложений — то же, что `/app` без текста.
- Домены — массовая покупка, покупка конкретного, только настройка. Дальше те же шаги, что у `/domain`.
- Расшарка — агентский аккаунт, TikTok, Unity, Snapchat. Бот спрашивает id и приложения по очереди.

Команды `/app`, `/domain`, `/share_*` по-прежнему работают сами по себе.

## Расшарка AppsFlyer

У AppsFlyer нет API на выдачу прав партнёру, бот открывает кабинет через Playwright. По умолчанию берёт **системный Chrome** (`AF_BROWSER_CHANNEL=chrome`), иначе Edge/`AF_BROWSER_PATH`, и только потом bundled Chromium — AF часто рвёт TLS к Chromium (`ERR_CONNECTION_CLOSED`). 

**Вход и сессия:** Логин по умолчанию — почта и пароль: `AF_EMAIL`, `AF_PASSWORD`. Кнопку Google бот сам не жмёт. Если в обычном Chrome вы входите через **Log in with Google / SSO**, а бот пишет ошибку входа — это нормально: парольная форма и Google — разные пути. **Рекомендуемая настройка:** `AF_HEADLESS=0` и `AF_LOGIN_MODE=manual` (или `python scripts/af_login.py`) — один раз войти руками (Google/SSO/пароль), сессия сохранится в `data/af_state.json` и будет использоваться автоматически. После этого можно вернуть `AF_HEADLESS=1` для фонового режима. Сессия действует неделями, пока AppsFlyer не разлогинит. Сохранение сессии атомарное (temp → replace), проверяется наличие auth cookies перед записью. При ошибке входа или блокировке (2FA/капча) хорошая сессия не перезаписывается. `AF_HEADLESS=1` по умолчанию, `0` — окно браузера. Таймаут: `AF_TIMEOUT_MS` (45000). Goto на сетевые обрывы ретраит до 3 раз.

После `pip install -r requirements.txt`:

```bash
playwright install chromium
# плюс установленный Google Chrome на машине бота (предпочтительно)
```

Так и на Windows, и на Linux.

Приложения — Android или iOS, несколько сразу: с новой строки, через пробел или запятую. Android: bundle или ссылка Google Play. iOS: ссылка App Store (`apps.apple.com`, любая страна, можно с query) или iTunes (`itunes.apple.com`), `id1234567890` или 9–12 цифр. В кабинет уходит `id` с префиксом. Ответ по каждому: готово / уже настроено / ошибка. Одно приложение не роняет остальные. Если на странице 2FA или капча, бот останавливается и пишет об этом. Скриншот ошибки лежит в `logs/`. На iOS баннер может говорить про IDFA вместо GAID — бот его не ждёт и идёт по тем же полям.

- `/share_partner <id или ссылка партнёра> <приложения>` — вкладка Permissions: все тумблеры, включая Send events revenue, события `af_app_opened`, `af_complete_registration`, `af_purchase`, отправка All media sources, including organic. Если события нет в выпадающем списке, бот пытается создать его свободным вводом (Enter/Tab/,). Дублирующиеся строки не создаются (идемпотентно).
- `/share_tiktok <TikTok App ID...> <приложения>` — `tiktokglobal_int`. Включает интеграцию, дописывает id без дублей, события LaunchAPP / Registration / Purchase, send-all и Values & revenue.
- `/share_unity <game id> <приложение>` — `unityads_int`. Несколько приложений: пара game id и приложение в каждой строке, или один game id и список приложений (Android или iOS). Game id пишется в General settings и во второе поле In-app event settings. События session / level_complete / purchase. После сохранения бот присылает click и impression ссылки.
- `/share_snapchat <Snap App ID...> <приложения>` — `snapchat_int`, события APP_OPEN / SIGN_UP / PURCHASE.

Если партнёр ещё не подключён к приложению, бот пробует открыть прямую страницу и кнопку Integrate. Этот экран на живом кабинете не снимался: если его нет, в чат уйдёт ошибка и скриншот, чужие настройки бот не трогает.
