# Бот завода приложений

Телеграм-бот на python-telegram-bot. Завод стартует только командой `/app`: либо `/app` и следующим сообщением текст о приложении, либо текст сразу после команды. Обычное пересланное сообщение само по себе ничего не запускает. Дальше шаги идут сами — кампания в Binom, карточка в CRM, домен, бэкенд. Архив, тематику, домен (если его не было в тексте) и ключи Facebook бот просит отдельно, их можно присылать обычным ответом.

Прогресс пишется в `data/workflows` и подхватывается после перезапуска.

## Настройка

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python bot.py
```

`ALLOWED_USER_IDS` — Telegram user id через запятую. Пустой список никого не пускает.

Ключи AppsFlyer и ссылка трекера Binom (`BACKEND_BINOM_URL`, без `?key=`) берутся только из `.env`.

## Шаги

0. `/app` — прислать данные приложения.
1. Разбор сообщения.
2. Кампания в Binom. Если имя уже есть — берём её, не клонируем.
3. Карточка в CRM. Если bundle/store id или имя уже есть — берём id, не создаём заново.
4. Домен: `app_domain` через `/app/update` и `domain` в правилах. Имя сверяется со справочником доменов.
5. Бэкенд: iOS — панель с cookie, Android — basic auth, перед этим ключи Facebook.

Ошибка останавливает цепочку и даёт кнопку «Повторить шаг». Уже сделанные шаги второй раз не гоняются. Id карточки CRM сохраняется сразу после создания, до выдачи доступа командам.

## /domain

Покупка на Dynadot (`DYNADOT_API_KEY`), зона в Cloudflare и запись в CRM. Белый список тот же.

Три режима, бот спрашивает кнопкой:

- Пачка: число N, только `.top` и `.sbs`. Имена вроде `backend42.top` / `dev7back.sbs`. Берём те, что свободны и не дороже `DOMAIN_MAX_PRICE_USD` (по умолчанию 3).
- Конкретные имена: цену показываем. Дороже лимита не выкидываем молча, спрашиваем.
- Только настройка: домены уже куплены. Список можно вставить столбиком, через запятую или из таблицы. Покупки нет.

Перед запуском список и кнопка. Дальше на каждый домен один аккаунт Cloudflare со статусом 0 в CRM: зона, A на `DOMAIN_DEFAULT_IP` (по умолчанию `5.75.214.90`, можно прислать другой), SSL flexible, NS в Dynadot, аккаунт помечается занятым, карточка домена в CRM. Для уже купленных срок берётся из Dynadot (`domain_info`), если его нет — сегодня плюс год. Ошибка по одному домену не останавливает остальные; упавший шаг можно повторить. Ключи и пароли в чат и в лог не пишутся.

## Меню

`/start`, `/menu` и `/help` показывают кнопки:

- Заведение приложений — то же, что `/app` без текста.
- Домены — массовая покупка, покупка конкретного, только настройка. Дальше те же шаги, что у `/domain`.
- Расшарка — агентский аккаунт, TikTok, Unity, Snapchat. Бот спрашивает id и приложения по очереди.

Команды `/app`, `/domain`, `/share_*` по-прежнему работают сами по себе.

## Расшарка AppsFlyer

У AppsFlyer нет API на выдачу прав партнёру, бот открывает кабинет через Playwright (Chromium). Логин только почта и пароль: `AF_EMAIL`, `AF_PASSWORD`. Кнопку Google не нажимает. Сессия пишется в `data/af_state.json` (файл в `.gitignore`) и подхватывается, пока её не разлогинит. `AF_HEADLESS=1` по умолчанию, `0` — окно браузера. Таймаут шага: `AF_TIMEOUT_MS` (45000).

После `pip install -r requirements.txt`:

```bash
playwright install chromium
```

Так и на Windows, и на Linux.

Приложения можно присылать bundle или ссылкой Google Play, несколько сразу: с новой строки, через пробел или запятую. Ответ по каждому: готово / уже настроено / ошибка. Одно приложение не роняет остальные. Если на странице 2FA или капча, бот останавливается и пишет об этом. Скриншот ошибки лежит в `logs/`.

- `/share_partner <id или ссылка партнёра> <приложения>` — вкладка Permissions: все тумблеры, включая Send events revenue, события `af_app_opened`, `af_complete_registration`, `af_purchase`, отправка All media sources, including organic.
- `/share_tiktok <TikTok App ID...> <приложения>` — `tiktokglobal_int`. Включает интеграцию, дописывает id без дублей, события LaunchAPP / Registration / Purchase, send-all и Values & revenue.
- `/share_unity <game id> <приложение>` — `unityads_int`. Несколько приложений: пара game id и bundle в каждой строке, или один game id и список приложений. Game id пишется в General settings и во второе поле In-app event settings. События session / level_complete / purchase. После сохранения бот присылает click и impression ссылки.
- `/share_snapchat <Snap App ID...> <приложения>` — `snapchat_int`, события APP_OPEN / SIGN_UP / PURCHASE.

Если партнёр ещё не подключён к приложению, бот пробует открыть прямую страницу и кнопку Integrate. Этот экран на живом кабинете не снимался: если его нет, в чат уйдёт ошибка и скриншот, чужие настройки бот не трогает.
